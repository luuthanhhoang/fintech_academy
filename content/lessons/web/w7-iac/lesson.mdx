<Callout kind="story" title="Đổi tên là xoá rồi tạo lại">
Một kỹ sư giả định đổi tên một tài nguyên database trong code hạ tầng cho dễ đọc. Diff trong pull request chỉ có một dòng, reviewer duyệt nhanh. Công cụ hiểu rằng tài nguyên tên cũ không còn trong code (cần xoá) và tài nguyên tên mới chưa tồn tại (cần tạo). Kết quả plan ghi rõ "1 to destroy" — nhưng không ai đọc plan.
</Callout>

## Hạ tầng dưới dạng code

Thay vì bấm trên console của nhà cung cấp đám mây, bạn mô tả hạ tầng trong file khai báo, để trong repo:

- **Tái lập**: dựng lại môi trường giống hệt (staging giống production).
- **Review**: thay đổi hạ tầng qua pull request như code.
- **Lịch sử**: ai đổi gì, khi nào, vì sao — có trong git.

Terraform là công cụ phổ biến; <Fact id="tf-license" />. Hai công cụ dùng cùng mô hình plan/apply/trạng thái.

## Plan, apply và trạng thái

1. **Code** mô tả trạng thái mong muốn.
2. **Trạng thái** (state file) ghi lại tài nguyên thật nào tương ứng với khai báo nào.
3. **Plan**: so code với trạng thái (và với thực tế) → danh sách tạo / sửa / **xoá** / **thay thế**.
4. **Apply**: thực hiện plan.

Một số thay đổi không sửa tại chỗ được mà buộc **xoá rồi tạo lại** — đổi tên tài nguyên, đổi một thuộc tính không thay đổi được. Với database, đó là mất dữ liệu. Vì vậy reviewer phải đọc **plan**, không chỉ diff code.

## File trạng thái

- Là **bản đồ** duy nhất giữa code và tài nguyên thật — mất nó, công cụ không biết mình quản lý gì.
- Thường chứa **giá trị nhạy cảm** (mật khẩu được sinh, chuỗi kết nối).
- → Lưu **từ xa**, **mã hoá**, **phân quyền**, có **khoá** để hai người không apply cùng lúc; **không commit** vào repo.

## Kiểm soát an toàn

- **Apply chỉ từ CI** với danh tính riêng; người không có quyền ghi trực tiếp vào production.
- **Plan trên mỗi pull request**, đăng kết quả để review; **phê duyệt** cho production.
- **Chặn xoá tài nguyên dữ liệu** (cờ bảo vệ chống xoá, chính sách kiểm tra plan).
- **Không sửa tay** trên console; nếu buộc phải sửa khi có sự cố, đưa lại vào code ngay sau đó. Chạy **phát hiện lệch** định kỳ.
- **Sao lưu đã thử khôi phục** cho dữ liệu — IaC không thay thế backup (xem case GitLab 2017 ở bài triển khai).

<Callout kind="field" title="Plan là thứ được duyệt, không phải code">
Quy tắc tôi đặt cho mọi repo hạ tầng: pull request phải có kết quả plan đính kèm, và bất kỳ dòng "destroy" hay "replace" nào trên tài nguyên có dữ liệu phải được người duyệt ghi rõ đã đọc và đồng ý. Diff code cho biết bạn định làm gì; plan cho biết công cụ sẽ thật sự làm gì.
</Callout>
