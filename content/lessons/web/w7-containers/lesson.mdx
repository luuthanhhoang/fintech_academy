<Callout kind="story" title="Image 2 GB có cả khoá API">
Một đội giả định đóng gói service bằng image dựa trên một hệ điều hành đầy đủ, `COPY . .` toàn bộ thư mục dự án — gồm cả `node_modules` của máy dev, thư mục `.git` và file `.env` chứa khoá API. Image nặng 2 GB, mất nhiều phút để kéo về mỗi lần triển khai, và được đẩy lên một registry mà nhiều người khác có quyền đọc.
</Callout>

## Container là gì

Không phải máy ảo nhỏ. Container là **một tiến trình bình thường** trên máy chủ, được nhân Linux:

- **Cô lập bằng namespace**: tiến trình chỉ thấy cây tiến trình, mạng, filesystem, hostname của riêng nó.
- **Giới hạn bằng cgroup**: CPU, bộ nhớ, I/O.

Vì dùng chung nhân của máy chủ, container khởi động nhanh và nhẹ hơn máy ảo; đổi lại mức cô lập yếu hơn máy ảo (có nhân riêng). <Fact id="oci-founded" />; các đặc tả của tổ chức này gồm **image spec** (lớp filesystem và cấu hình), **runtime spec** (cách tạo container từ một bundle, gồm namespace và cgroup trên Linux) và **distribution spec** (API của registry) — nhờ vậy image build bằng công cụ này chạy được trên runtime khác.

## Image và các lớp

Image là chồng **lớp filesystem** chỉ đọc cộng **cấu hình** (lệnh chạy, biến môi trường, user). Mỗi bước trong Dockerfile tạo một lớp; bước không đổi được **dùng lại từ cache**.

```dockerfile
# Stage build
FROM node:22-slim AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage chạy
FROM node:22-slim
WORKDIR /app
COPY --from=build /app/dist ./dist
COPY --from=build /app/node_modules ./node_modules
USER node
CMD ["node", "dist/server.js"]
```

- **Chép lockfile và cài dependency trước**, chép code sau → sửa code không phải cài lại dependency.
- **Multi-stage**: công cụ build ở lại stage build; image chạy nhỏ hơn, ít bề mặt tấn công hơn.
- **Ghim phiên bản** base image (tốt hơn nữa: digest) để build tái lập được.
- **`.dockerignore`**: loại `.git`, `node_modules` của máy, `.env`, file test.

## Image cho production

- **Không có bí mật trong image**: mọi lớp đều đọc lại được, kể cả khi bước sau xoá file. Bí mật đi vào lúc chạy (biến môi trường từ kho bí mật, file mount).
- **User không phải root**; filesystem chỉ đọc khi được.
- **Cấu hình bằng biến môi trường** — cùng image chạy ở mọi môi trường (bài triển khai).
- **Log ra stdout/stderr**, để nền tảng thu thập (bài quan sát).
- **Healthcheck** cho bộ điều phối biết khi nào container sẵn sàng/hỏng.
- **Quét lỗ hổng** và cập nhật base image định kỳ — container đóng gói cả lỗ hổng của dependency.

## Những gì container không giải quyết

- Không làm code an toàn hơn: lỗ hổng ứng dụng (bài bảo mật web) vẫn nguyên.
- Không tự đảm bảo dữ liệu bền: filesystem của container mất khi container bị xoá — dữ liệu cần volume hoặc dịch vụ lưu trữ.
- "Chạy giống nhau" chỉ đúng với những gì nằm trong image; khác biệt về cấu hình, dữ liệu, mạng, phiên bản nhân vẫn có thể gây khác hành vi.

<Callout kind="field" title="Image là thứ được kiểm thử, cũng là thứ được triển khai">
Quy tắc tôi giữ: CI build image đúng một lần, gắn tag bằng commit, chạy test trên chính image đó, rồi đẩy đúng image đó qua staging lên production. Không build lại "cho production". Khi có sự cố, tag của image cho biết chính xác code nào đang chạy — và rollback là đổi tag, không phải build lại một bản cũ mà không chắc có giống trước không.
